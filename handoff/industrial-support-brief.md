# 工业设备客服训练器与版本化手册接入草稿

## 交付目标

让客服训练器使用显式配置，在只有公共源码和合成夹具的环境中完成一次 CPU 训练与重载。客服回答设备问题时，先按型号和硬件版本找手册，再给出带章节的答复。问答训练样本负责练习追问、解释依据和转人工。

## 工程范围

| 相对路径 | 工作内容 |
| --- | --- |
| `train/train.py`、`config/train.yaml`、`config/model.yaml` | 保留现有训练命令及参数。由入口传入本产品的配置、数据源和输出目录。 |
| `lm_trainer/` | 独立维护训练配置校验、`text` 数据加载、量化、HF 和可选 Unsloth 后端、通用生成和导出。先核对交付源码中的文件及 SHA-256，再选择采用范围。 |
| `examples/industrial_support/` | 使用新编的设备标识、手册片段和客服问答。手册按型号、硬件版本、文档版本及章节管理。 |
| `tests/`、`lm_trainer/tests/` | 添加 CPU 合成回归、版本查证与异常路径测试。 |

## 验收用例

1. 在空目录放入交付清单中的文件，清除 `PYTHONPATH`，使用已有 HF 环境。运行 `python -m lm_trainer --help`，再用 `--config`、`--model-config` 和 `--dry-run` 检查显式配置。分别验证缺配置文件、缺数据、缺型号和缺手册时的反馈。
2. 用临时创建的小模型和三条长度不同的合成文本，批大小设为 1、梯度累积设为 2。核对两个优化器更新、尾窗、调度器步数和有效目标数。分别覆盖保存间隔命中与未命中。独立进程重载 `final`，检查关闭、开启、再关闭 adapter 时的输出。记录产物支持的用途。
3. 在无 Unsloth 的 HF 环境完成上述验收。可选后端用显式开关与独立解释器，单独记录配置检查、工厂接线及实际运行结果。
4. 用虚构设备 XR-17 演示查证。硬件 A 的就绪灯为青色，引用 `XR17-A-1 §2`。硬件 B 为琥珀色，引用 `XR17-B-2 §4`。省略版本时追问。版本无对应手册或匹配到冲突条目时说明证据不足并提供转人工选项。
5. 交付本次批准的一组源码文件、逐文件 SHA-256、CPU 复跑命令、结果和上一批准版本标识。先预览整组差异，再用干净源码运行测试。出现缺项、类型变化或测试失败时保留原版本。需要回退时按组恢复上一版本并复跑同一套检查。

示例查询可运行 `python -m examples.industrial_support XR-17 --revision B`。CPU 回归可运行 `CUDA_VISIBLE_DEVICES='' ACCELERATE_USE_CPU=true HF_HUB_OFFLINE=1 python -B -m pytest -p no:cacheprovider -q lm_trainer/tests`。将尚未实测的设备和运行模式列在交付记录中。
