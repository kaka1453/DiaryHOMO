# Task B｜阶段、Adapter 注册与基准 v1

**入口。** 旧 `legacy` 及 Task A 未显式选择生命周期的入口保持兼容。Task B 使用单阶段 YAML 或 `stages: [...]`，每个阶段显式 `name/objective/init_adapter/lr/max_steps/output_dir`，可配独立预算、长度、seed、accumulation、模板和数据源；不从列表上层继承 `epochs/max_steps`。`packing` 必须为 `false`。`--validate-release`/`--dry-run` 做轻量门禁，`--simulate-only` 增加实际分词、预算和批次检查，均不加载基座张量。见 [可复跑示例](../examples/vision_support/BENCHMARK_REPORT.md)。

**生命周期。** 阶段要求 `lora_bias: none`，保证全部基座参数冻结。HF `new` 只注入一次 LoRA；`continue_stage` 只接受显式 `parent`，用 `PeftModel.from_pretrained(..., is_trainable=True)` 保持 FP32 LoRA（即使基座为 BF16/FP16），逐 tensor 校验名称、形状、dtype 和数值，不做合并，重建 AdamW、线性 scheduler、seed 和采样计划。CPT 若作为 SFT 的父阶段，配置同一原生 `template_policy` 用于绑定，**不**用它渲染 CPT 样本。`stage:<name>` 只能引用同一显式计划中之前阶段的 `final`。正式任务由人工依据 dev 选择父产物，不查找 `latest`。锁定版 Unsloth 仅支持 `new`；继承/同阶段恢复请从 **HF 父阶段** 开始，不跨后端加载。

**断点。** `checkpoint_N` 是 `training_checkpoint`，含 LoRA、AdamW、scheduler、可选 GradScaler、Python/NumPy/CPU/CUDA RNG、采样计划指纹及已消费 epoch/batch、累计 token/曝光和配置身份。采用 `torch.load(weights_only=True)`，仅在成功 optimizer update 后存档；worker 预取游标不是消费游标。`--stop-after-updates K` 模拟安全暂停，不发布 `final`。`resume` 指向具体 `resume_from`，写全新的 `output_dir`，沿用 `run_id` 并记录 `resume_checkpoint_sha256`。模型、数据、模板、seed、预算、有效环境等不匹配即拒绝。CPU FP32 和本机 RTX 3090 FP16/NF4 冒烟均验证逐元素精确（`rtol=atol=0`）；不保证跨设备、跨依赖或未验证的量化 CUDA 内核精确复现。现有目录不覆盖。异常只可能留下已完成的 checkpoint 或隐藏暂存，不发布半成品 `final`。

**Task C：`final/training_manifest.json`。** `schema=lm_trainer.adapter-artifact.v1`、`artifact_kind=inference_adapter`、`adapter_format=peft_lora_safetensors`。`verify_artifact(dir, expected_sha256=...)` 返回 `(manifest, manifest_sha256)`，默认拒绝 fixture；预览需显式 `allow_fixture=True`。`artifacts` 是完整的相对文件名 → SHA-256 映射，验证非空、无 symlink、PEFT LoRA 结构，checkpoint 不能作为推理输入。哈希不证明授权来源；可信注册表应 pin manifest SHA 并使用不可变产物目录。调用方再用 `base_fingerprint()` 对比 `base_model`（本地实际 safetensors 文件、config、shard index、可选 revision），用 `tokenizer_hash()`、`policy_identity()` 比对加载的 fast tokenizer 与运行模板策略，然后在显式基座模型上挂载 PEFT。PEFT config 的 `base_model_name_or_path` 有意置空；不要依赖它下载基座。应用 system prompt 不写入 manifest，由可信应用配置提供，用 SHA 对比。目录 [task_b_fixture_adapters](../examples/vision_support/task_b_fixture_adapters/) 提供仅限测试的 CPT/SFT 和基座重建指针。

**Task D：报告。** 按 `run_id/stage_name/objective/seed` 关联，使用 `parent_adapter_sha256` 和 `resume_checkpoint_sha256` 追踪谱系；训练入口记录 release ID、data manifest SHA、`split=train`、`fixture_only`。`planned_vs_actual_tokens` 和 `performance.json` 分来源对比真实 input、causal-shift loss、正文/EOS、unique、累积曝光与未用预算。`updates` 包含实际批次顺序和张量哈希、loss、输入/目标 token 数、样本数和同步耗时。`dev` 是最近一次评估，`dev_history` 是按 update 的轨迹；只读取分离且无训练事件或源 ID 重叠的 `dev` 清单，默认不保存生成文本。`lm_trainer.benchmark.v1` 聚合 `status/cases/cross_backend_parity/aggregate`，吞吐为 sum(actual)/sum(seconds)；预热排除，未测为 `null`。Fixture 只证明工程链路，不证明业务质量。
